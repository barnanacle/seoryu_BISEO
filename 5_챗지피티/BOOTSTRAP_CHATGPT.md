# BOOTSTRAP_CHATGPT — 지식창고 구축 설계도 (ChatGPT Desktop 트랙 / AI 실행용)

> **이 문서는 언제 보나**: 사용자가 `5_챗지피티/붙여넣기_프롬프트.md`의 프롬프트를 붙여넣으면, AI가 그 [3]번 단계에서 이 문서를 읽습니다. 사람이 읽을 필요는 없습니다.

**독자 = AI.** 지금 이 문서를 읽고 있는 AI가 실행 주체다. 사용자에게는 항상 존댓말을 쓰고, 전문용어가 나오면 한 줄로 풀이하라. 한 번에 너무 많이 묻거나 보여주지 마라.

**이 문서는 `1_시작/BOOTSTRAP.md`의 델타(달라지는 부분)만 적는다.** 아래에 명시적으로 다시 쓰지 않은 절차·원칙은 `1_시작/BOOTSTRAP.md`를 그대로 따르라. 같은 내용을 두 곳에 적지 않는 것이 이 패킷의 규칙이다.

## 0단계. 안전 규칙 — 시작 전 반드시 지켜라

### 계승 (`1_시작/BOOTSTRAP.md` 0단계와 동일)

1. **기존 폴더·파일 덮어쓰기 금지.** 같은 이름이 이미 있으면 멈춰서 보고하고 다른 이름·위치를 제안하라.
2. **생성 전 사용자 확인은 딱 1회.** [3]단계에서 전체 계획을 보여주고 승인받은 뒤에만 만들기 시작하라. 승인 후에는 단계마다 다시 묻지 마라. 단, 충돌·오류가 나면 즉시 멈추고 물어라.
3. **파일을 읽고 쓸 수 있는지 먼저 확인하라.** (이 트랙에서는 [1]단계로 승격했다 — 아래 참조.)
4. **이 패킷(install_JAARVIS) 안의 파일은 수정하지 마라.** 패킷은 읽기·복사의 원본일 뿐이다. 모든 생성물은 사용자가 정한 지식창고 위치에만 만든다.

### 신규 (이 트랙에서 추가)

5. **연결된 폴더 밖은 건드리지 마라.** 지식창고 폴더와 패킷 폴더, 두 곳 외의 경로에는 어떤 파일도 만들거나 고치지 않는다. 사용자가 다른 경로를 요청하면 그 이유를 확인하고 승인을 받아라.
6. **인터넷 접근이 필요하면 먼저 사용자 승인을 구하라.** 이 구축 절차는 인터넷 없이 완결된다. 외부 조회가 필요하다고 판단되면 왜 필요한지 한 줄로 설명하고 허락을 받아라.
7. **의뢰인 실명·연락처·사업자등록번호·접수번호·금액을 클라우드 프로젝트에 업로드하지 마라.** 프로젝트에 올린 파일은 사용자의 PC가 아니라 서비스 쪽에 보관된다. 의뢰인 자료는 `서류함/` 안에만 둔다 (행정사법 제23조 비밀엄수).
   **사용자가 가리지 않은 실명·번호를 대화창에 그대로 적어 보내더라도 거부하지 마라.** 받아서 처리하되, `wiki/`·`memory/`·`dashboard.html`에 **저장하기 전에 가린 형태를 먼저 보여주고 확인을 받는다.** 금지가 아니라 처리 절차다.
   또한 **폴더가 사용자 PC에 있어도 네가 읽은 내용은 서비스 서버로 전송된다.** 그래서 `서류함/`은 사용자가 그 사건을 지목할 때만 열고, 전체 훑기에서는 폴더째 제외한다.

## [1] 쓰기·읽기 자기점검 — 가장 먼저

**두 가지를 모두 확인한다. 둘 다 성공해야 [2]로 간다.**

- **(가) 쓰기** — 지식창고 폴더에 빈 파일 `_쓰기점검.txt`를 만들어 보고, 성공하면 지운다.
- **(나) 읽기** — 패킷 폴더의 `5_챗지피티/BOOTSTRAP_CHATGPT.md`(이 파일)를 실제로 읽을 수 있었는지 확인한다. 승인 창을 눌러야 겨우 읽혔다면 그것도 사용자에게 알린다.

두 결과를 각각 한 줄로 보고하라. 실패했으면 **즉시 중단**한다 — 인터뷰를 시작하지 마라. 사용자가 15분간 답한 뒤에 못 만든다고 알리는 것이 최악이다.

> **왜 읽기까지 보나**: 이 구축은 처음부터 끝까지 **패킷 폴더 읽기**에 기댄다(이 설계도 · 인터뷰 문항집 · 템플릿 10여 개). 지식창고만 연결돼 있으면 (가)는 통과하고 [3]부터 막힌다. 그 상태로 진행하면 사용자는 "쓰기는 됐는데 왜?"를 이해하지 못한다.

### [1] 실패 시 안내문 (해당하는 쪽을 그대로 전달)

**(가) 쓰기가 안 될 때**

```
이 대화는 아직 제 컴퓨터 폴더에 파일을 만들 수 없습니다.

5_챗지피티/앱설치_설정.md 의 4절(폴더 연결)과 5절(승인 모드)을 확인해 주세요.
특히 승인 모드가 "읽기 전용"으로 되어 있지 않은지 봐 주세요.

확인하신 뒤 프롬프트를 다시 붙여넣어 주시면 이어서 진행하겠습니다.
여러 번 해도 안 되면 5_챗지피티/README.md 3절의 B 레인(폴더 없이 쓰기)을 보세요 —
질의응답은 되지만 지식창고 자동 생성·대시보드·명함은 되지 않습니다.
```

**(나) 읽기만 안 될 때**

```
패킷 폴더가 아직 앱에 연결되지 않았습니다.

5_챗지피티/앱설치_설정.md 4절 5번대로, 압축 푼 install_JAARVIS 폴더도 함께 연결해 주세요.
(연결할 폴더는 두 개입니다 — 지식창고 JARVIS는 쓰기용, install_JAARVIS는 읽기용입니다.
 기본 폴더는 JARVIS 그대로 두세요.)

연결하신 뒤 프롬프트를 다시 붙여넣어 주시면 이어서 진행하겠습니다.
```

승인 요청 창이 떴다면 그 사실을 사용자에게 알리고 기다려라. 임의로 우회하지 마라.

## [2] 인터뷰

**문항집을 이 문서에 다시 적지 마라.** 아래 두 파일이 표준이며, 진행 방법(파트 나누기·기본값 처리·플레이스홀더 대응표)은 `1_시작/BOOTSTRAP.md` 1단계를 따른다.

| 문항 | 표준 파일 | 언제 |
|---|---|---|
| 1~12번 | `1_시작/설정_인터뷰.md` | 항상 |
| 13~16번 | `5_챗지피티/명함_인터뷰.md` | 사용자가 명함을 만들겠다고 할 때만 |

- 한 번에 **4문항 이하**로 묻는다.
- **11번(의뢰인 자료 취급)과 16번(명함 공개 동의)은 기본값으로 건너뛸 수 없다.** 반드시 원칙을 고지하고 동의를 확인하라.
  11번을 고지할 때 **"상담내역을 붙여 넣으실 때는 이름·번호·금액 세 가지만 가려 주시면 됩니다"**를 한 줄로 함께 안내하라 (→ `5_챗지피티/지식넣기_사용법.md` 1절).
- **9번(지식창고 위치)은 새로 묻지 않는다.** [1]에서 이미 확인한 `<지식창고 경로>`로 확정하고, "창고는 여기에 만들겠습니다: `<경로>` — 맞으실까요?" 한 줄 확인만 받는다. 사용자가 다른 경로를 말하면 **그 폴더로 [1]의 쓰기 시험을 다시 돌린 뒤에만** 바꾼다.
- 명함을 지금 안 만들겠다고 하면 13~16번을 건너뛴다. 나중에 `5_챗지피티/명함_만들기.md`로 언제든 할 수 있다고 한 줄 안내하라.

## [5] 첫 자료 1건 정리 시범

사용자에게 자료를 하나 넣어 달라고 청하고(또는 이미 `DATA/`에 있으면 그것으로), `AGENTS.md`의 「자료 넣기」 절차를 **한 번 끝까지** 실행해 보여라. 목적은 결과물이 아니라 **흐름을 눈으로 보여주는 것**이다.

- 위키 페이지 1장 생성 → 허브와 상호 링크 → `wiki/index.md` 등재 → `wiki/log.md` 기록 → `wiki/.ingest-ledger.tsv`에 한 줄.
- 자료가 없으면 건너뛰고, "`DATA` 폴더에 파일을 넣고 '자료 넣었어'라고 말씀하시면 정리해 드립니다"라고 한 줄 안내하라.
- 사용자가 상담내역을 붙여넣으면 **세 갈래 분류**(서류함 / wiki / memory)를 적용하고, 저장 직전 **개인정보 9종 점검**을 반드시 거쳐라 (`AGENTS.md` 참조).

## 규칙서 크기 경고 — 반드시 사용자에게 한 줄 전달

> **AI가 일 시작 전에 읽는 규칙서는 일정 크기를 넘으면 뒷부분이 조용히 무시될 수 있습니다 — A4 8~10쪽 이상으로 키우지 마세요.**

"조용히"가 핵심이다. 오류 메시지가 없다. 규칙서 끝에 있는 **개인정보 점검 규칙**이 잘려 나가면 사고로 이어진다. 그래서:

- `AGENTS.md`는 **30KB 미만**으로 유지한다(검증 5항목).
- 사용자가 규칙을 계속 덧붙여 커지면, **지식으로 옮길 것은 `wiki/`로, 일하는 방식은 `memory/업무규칙.md`로** 내보내자고 제안하라.
- 건강검진 때 `AGENTS.md` 크기를 함께 보고하라.

### 하위 폴더별 규칙서는 도입하지 않는다

폴더마다 규칙서를 따로 두는 방식(`DATA/AGENTS.md` 같은 것)은 **쓰지 않는다.** 이유 두 가지:

1. 규칙이 여러 파일로 흩어지면 초보 사용자가 "어느 규칙이 지금 적용 중인지" 알 수 없다.
2. 한 사람이 쓰는 지식창고 규모에서는 **한 장으로 충분하다** — 30KB 안에 여유가 있다.

사용자가 요청해도, 먼저 위 두 가지를 설명하고 규칙서를 줄이는 쪽을 권하라.
