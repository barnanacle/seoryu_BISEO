# 배포 검증 기록

검증일: 2026-09-06. 실제 실행 환경: macOS, Python 3.12.14, python-docx 1.2.0, pypdf 6.10.0, pdfplumber 0.11.9, reportlab 4.4.9, Pillow 12.3.0, numpy 2.3.5, lxml 6.1.1. LibreOffice와 Poppler로 변환·검사했다. Windows에서의 실제 실행 검증은 포함하지 않았다.

| 검증 | 결과 |
|---|---|
| 데이터·대화 순서·레이아웃 단위 검사 | 48개 통과 |
| 레이아웃 대표 사례 | 8개 생성 통과, 추가 쪽 삽입 오류 감지 통과 |
| 식품위생 가상 사례 | 행정사용·셀프용 각각 질문지, 응답 대기, 전체 DOCX·PDF, 증빙 변경 후 v002까지 통과 |
| 독립된 새 설치 위치 | 설치 후 셀프 흐름을 PDF 공문부터 v002까지 실행하여 통과 |
| 재설치 | 기존 파일 내용 보존, 누락 항목만 복사 |
| 공개·설치 제외 | 실제 사건·산출·임시 파일·가상환경 제외 |
| 글꼴 | 임베딩된 글꼴이 동봉 OFL 나눔 원본과 같은지 확인 |
| 별지 일치 | 합본 PDF, 별지 DOCX 재변환, 전체 편집 DOCX의 별지, 반복 변환을 쪽별 픽셀 비교하여 차이 0 |

대표 레이아웃은 기본 사례, 개인·날짜 미상, 긴 성명·주소, 소명 6개, 소명 0개, 기관 서식 2쪽, 서식 미확정, 표지 이미지 합성을 포함한다. 여러 칸에 같은 ‘확인 필요’가 있어도 각 칸의 좌표에서 해당 값을 찾고, 다른 칸의 문구로 누락이 가려지지 않는 회귀 검사를 추가했다. 질문지에서도 질문과 답변란이 같은 쪽에 있고 모든 질문이 빠짐없이 출력되는지 검사한다.

질문지와 의견서 PDF의 모든 쪽을 렌더링하여 표지·라벨·줄바꿈·쪽 나눔을 시각 점검했다. Word의 모든 버전이나 ChatGPT 내장 DOCX 미리보기에서 같은 화면이라는 뜻은 아니다. 첫 장의 공식 서식 배경은 고정되며 그 위 입력값과 별지 본문은 편집 가능하다.

## 다시 검사하기

도구 폴더에서 다음 순서로 실행한다.

```bash
python3 bin/doctor.py
python3 bin/run_checks.py
python3 bin/run_layout_suite.py
python3 bin/run_flow_demo.py
```

꾸러미 저장소 루트에서는 `python3 dev/tests/test_runtime_install.py`로 설치·기존 파일 보존·제외 규칙을 확인한다. 검사 산출은 모두 `산출/` 아래에 생기며 커밋하지 않는다.

가상 사례의 법률검토는 특정 날짜에 확인한 원문 기록이다. 새 사건의 적용 시점, 최신 개정, 특별규정 및 실제 상담 내용을 다시 검토해야 한다. 프로그램의 검증은 법률 결론이나 사실의 진실성, 기관 접수를 자동 보증하지 않는다.
