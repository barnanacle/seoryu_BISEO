# 행정처분 의견서 초안 작성기

처분청의 사전통지를 읽고 **질문지부터** 만듭니다. 행정사는 잠재 의뢰인 상담에, 셀프 이용자는 본인의 대응 사실을 찾는 데 사용합니다. 이용자는 JSON이나 명령어를 직접 다룰 필요 없이 같은 AI 대화에서 계속 답하면 됩니다.

## 두 번의 입력으로 시작

**첫 입력 — 사전통지서와 모든 붙임을 첨부합니다.**

> 행정처분 의견서 작성기를 사용해 이 사전통지의 처분 내용·기한·관련 규정을 확인하고, 불처분·예정 처분 변경과 감경 등을 검토할 질문지를 먼저 만들어줘. 나는 행정사야. (또는 내가 직접 대응할 거야.)

AI는 통지된 위반의 성립요건, 처분 권한·차수·범위, 감경·면제·과징금 갈음 가능성과 제외사유를 해당 사건의 법령으로 확인합니다. 질문지에는 **관련 규정 → 법적 요건 → 확인할 질문 → 필요한 자료**를 함께 적습니다. 감경 제도가 없거나 원문을 확인하지 못했다면 그 상태를 밝힙니다. 통지의 주장을 곧바로 본인의 인정 사실로 삼지 않습니다.

**두 번째 입력 — 같은 대화에 질문 번호별 답변 또는 상담 채팅·녹취 전사문을 넣습니다.**

> 앞서 만든 질문지에 대한 답변(상담기록)이야. 이 기록과 확인된 자료만으로 의견제출서와 별지 초안을 만들고, 필요한 소명자료 목록도 정리해줘. 모르는 내용은 【확인 필요】로 남겨줘.

AI가 질문별 답변과 원문의 쪽·행·시각을 대조한 후 다음을 생성합니다.

- 일반 의견제출에 적용되는 **[별지 제11호서식] + 상세 별지 PDF 한 파일**
- **의견제출서 전체 편집본 DOCX**: 첫 장의 입력값과 별지 본문을 수정 가능
- 별지만 편집하는 DOCX
- 소명자료 요청목록, 논거·증빙 대조표, 법률검토, 제출 전 확인사항

처음부터 상담기록을 함께 주어도 질문지를 먼저 제시하고 그 기록을 답변으로 연결합니다. 상담 음성을 자동 전사하는 기능은 포함하지 않습니다. 화자·시각이 있는 전사문을 입력합니다.

## 수정과 제출 준비

새 자료·정정 답변·DOCX 수정본을 같은 대화에 넣으면 해당 사실, 논거, 취지·결어와 자료 목록을 함께 재검토합니다. 질문이나 법률 요건이 바뀌면 새 질문지를 만들고 답변을 다시 대조합니다. 이전 원문·초안은 보존하고 v002, v003으로 생성합니다.

자료 번호는 의뢰인용·제출용 문서에서 **소명자료 1, 소명자료 2**로 표시합니다. E001은 내부 연결 ID(Evidence)이며 법정 번호가 아닙니다. 요청 예정·수령·검토 완료·첨부 예정을 구분합니다. 실물을 받지 않은 자료를 첨부한 것으로 쓰지 않습니다.

본인 또는 담당 행정사는 기한, 사실, 법률 판단, 서명권자와 첨부 실물을 확인하고 수정한 DOCX를 제출용 PDF로 변환합니다. 작성기는 기관에 자동 발송하거나 접수하지 않습니다.

## 범용 적용의 범위

업종·개인/법인·처분 종류·소명 개수를 고정하지 않습니다. 사전통지 단계에서의 불처분·예정 처분 철회/변경 요청과 이미 확정된 처분의 취소·행정심판·소송을 구분합니다. 확정 처분은 이 사전 의견제출 경로에서 생성하지 않습니다.

일반 의견제출, 청문, 과태료, 특별법 절차를 먼저 분류합니다. **모든 사전통지에 별지 제11호를 적용하지 않습니다.** 특별 서식은 실제 기관 PDF와 확인한 좌표를 등록합니다. 서식이 미확정이면 ‘제출 서식 확인 필요’ 표지가 붙은 검토 초안을 만듭니다. 각 분야의 법률 판단이 미리 탑재된 서비스가 아니므로 사건마다 법령 도구와 공식 원문 확인이 필요합니다.

## 동작 방식과 설치

이 도구는 AI 대화에서 실행하는 로컬 꾸러미입니다. 폴더에 파일을 넣는 것만으로 AI가 자동 실행되는 백그라운드 서비스는 아닙니다. AI가 공문을 읽고 법령을 조회해 구조화하며, 프로그램은 순서·출처 연결·변경 여부와 문서 레이아웃을 검증합니다. 검증 통과가 법률 판단의 진실성을 보장하지는 않습니다.

Python 3.10 이상과 `requirements.txt`의 문서 패키지, LibreOffice, Poppler의 `pdftoppm`이 필요합니다. Codex의 문서 런타임이 있으면 자동 탐색합니다. 없으면 해당 프로그램을 설치하고 다음처럼 가상환경에 문서 패키지를 준비합니다. 아래 명령은 이 도구 폴더에서 실행합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bin/doctor.py
```

Windows에서는 `python`, `.venv\Scripts\python.exe`를 사용합니다. 실행 파일을 못 찾으면 `JAARVIS_OPINION_PYTHON`, `JAARVIS_OPINION_SOFFICE`, `JAARVIS_OPINION_PDFTOPPM` 환경변수로 각각 지정할 수 있습니다. macOS에서 실제 변환을 검증했으며 Windows 실행은 별도 환경 검증이 필요합니다. 실행환경이 없으면 오류를 표시하며 다른 변환 엔진으로 조용히 대체하지 않습니다.

## AI 운영과 개발 점검

AI는 [AGENTS.md](AGENTS.md), [사용 순서](사용_시퀀스.md), [데이터 명세](사건데이터_명세.md)를 읽습니다. 대화별로 사건을 연결하며 ‘최근 사건’ 공용값을 사용하지 않습니다.

```bash
python3 bin/dialogue_flow.py start --conversation 대화고유키 --notice '/문서/사전통지.pdf' --audience professional
# 공문·관련 법규·요건 C·질문 Q를 case.json에 작성한 뒤
python3 bin/dialogue_flow.py questionnaire --conversation 대화고유키
# 이용자에게 질문지를 제시하고 답변을 받은 뒤
python3 bin/dialogue_flow.py respond --conversation 대화고유키 '/문서/답변.txt'
# 답변별 출처·사실 F·법규 L·논거 A·자료 E·본문을 작성하고 실제 검토한 뒤
python3 bin/case_workflow.py review '산출/사건/사건ID/case.json' --reviewer 'AI 초안 검토' --note '실제로 수행한 검토 내용'
python3 bin/dialogue_flow.py draft --conversation 대화고유키 --no-open
python3 bin/run_checks.py
python3 bin/run_layout_suite.py
```

질문지와 답변 연결이 없거나 변경 후 재검토가 없으면 초안을 생성하지 않습니다. 답하지 않은 질문은 `unknown`과 확인 필요 사유를 남깁니다. `review`는 실제 검토 이후 기록하는 명령이며 사실이나 법령을 자동 확인하는 명령이 아닙니다.

출력·원문 사본·검증 자료는 `산출/사건/사건ID/` 아래에, 임시 파일은 `산출/_tmp/`에 생성됩니다. 의뢰인 자료와 생성물은 공개 저장소에 포함하지 않습니다. Git 제외와 설치 제외를 함께 적용합니다.

## 레이아웃

별지는 **DOCX를 먼저 작성하고 그 파일로 PDF를 변환**합니다. 독립 재변환과 반복 변환의 전체 별지 픽셀이 같은지 검사합니다. 전체 편집본 안의 별지도 같은 검사를 거칩니다. 칸 넘침·문단 누락·쪽수·자간·라벨 정렬 오류를 검사합니다.

전체 DOCX의 첫 장은 공식 빈 서식 배경 위에 입력값을 편집 가능한 텍스트 상자로 둡니다. 빈 서식 선과 고정 문구는 배경입니다. 표지 PDF는 공식 PDF 원본 위에 값을 합성합니다. 별지 본문은 Word에서 직접 편집할 수 있습니다. ChatGPT 내장 DOCX 미리보기는 자간·장평·줄바꿈을 다르게 표시할 수 있어 지면은 생성 PDF로 확인합니다.

배포본은 나눔명조·나눔고딕을 문서에 포함하며 라이선스는 `THIRD_PARTY_NOTICES.md`에 있습니다. 원본 프로젝트는 기존 글꼴 프로필을 유지합니다.
