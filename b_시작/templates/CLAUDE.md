## 폴더 구조

```
지식창고/
├── CLAUDE.md                ← 헌법 (이 파일 — 운영 규칙 전부)
├── AGENTS.md                ← 헌법 사본 (Codex 앱용 — 내용 동일 유지)
├── 시작프롬프트.md          ← 매 대화 첫머리에 끌어다 놓는 파일
├── 1_수집자료실/            ← 자료 상자: 원본을 넣기만 하는 곳 (AI는 읽기만, 절대 수정 안 함)
├── wiki/                    ← 지식 창고: AI가 정리·관리하는 곳
│   ├── index.md             ← 전체 목차 (카테고리별)
│   └── log.md               ← 작업 일지 (무엇을 언제 정리했나)
├── memory/                  ← 기억 노트: 내 스타일·피드백·규칙
│   └── MEMORY.md            ← 기억 목차 (한 줄씩)
├── 2_수임업무철/            ← 의뢰인 사건 자료 (wiki에 실명 반영 절대 금지 구역)
├── 3_문서작업실/            ← 내가 만드는 산출물 (의견서·계약서 등)
└── tools/                   ← 변환 도구 (hwp·pdf 등 → md)
```

- `1_수집자료실/` 하위 폴더는 자유롭게 만든다 (예: 인허가/, 계약서/, 민원/).
- `wiki/` 안은 하위 폴더 없이 평평하게 관리한다. 분류는 `wiki/index.md`가 담당한다.
- `2_수임업무철/`·`3_문서작업실/`·`tools/`의 파일은 자동 정리(Ingest) 대상이 아니다.

## 기억 3층 구조

| 층 | 파일 | 언제 읽나 |
|---|---|---|
| 1. 헌법 | `CLAUDE.md` / `AGENTS.md` | 매 대화 (그래서 작게 유지) |
| 2. 인덱스 | `wiki/index.md` · `wiki/log.md` · `memory/MEMORY.md` | 매 대화 (한 줄씩이라 가벼움) |
| 3. 본문 | `wiki/*.md` · `memory/*.md` 개별 파일 | **필요할 때만** AI가 찾아 읽음 |

헌법과 인덱스(목차)만 매번 읽고, 본문은 필요할 때만 찾아 읽는다.
그래서 지식이 수천 페이지로 늘어도 대화가 느려지지 않는다 — 사실상 "무제한 기억"이 된다.
(원리가 궁금하면: 설치 꾸러미의 `d_사용법/지식얼개_원리.md` — 도서관의 서가·목록카드·사서 규칙 비유)

## 세 가지 동작

### 1. 자료 넣기 (Ingest) — 트리거: "자료 넣었어" / "이거 정리해줘"

사용자가 `1_수집자료실/`에 파일을 넣고 말하면 다음 6단계를 실행한다.

1. **스캔** — `1_수집자료실/`을 훑어 아직 정리하지 않은 파일을 찾는다. 판별 기준은 **처리 대장** `wiki/.ingest-ledger.tsv`(한 줄 = 처리한 파일 하나)와의 대조다 — 대장에 없는 파일만 새로 정리한다. 대장 파일이 없으면 이때 새로 만든다. (일지 본문을 파일명으로 검색해 판별하는 방식은 쓰지 않는다 — 같은 파일을 여러 번 재판정하는 낭비가 생긴다.)
2. **읽기** — 원본을 읽고 내용을 파악한다. 원본은 절대 고치지 않는다.
3. **위키 페이지 생성** — `wiki/`에 새 페이지를 만든다. 맨 앞 `> **핵심**` 콜아웃 3줄 필수.
4. **교차연결** — 기존 위키 전체를 훑어 관련 페이지를 찾고, 양방향 `[[위키링크]]`를 건다.
   **새 페이지는 양방향 연결 2개 이상(가급적 분야를 넘는 연결 1개 포함)을 만들고 시작한다** — 못 채우면 연결 후보를 한 줄 제안하고 "연결 부족" 표시를 남긴다. (연결 없는 외딴 페이지는 나중에 아무도 못 찾는다.)
5. **index 등재** — `wiki/index.md`의 알맞은 카테고리에 새 페이지를 한 줄 추가한다.
6. **log 기록** — `wiki/log.md` 맨 위(오늘 날짜)에 무엇을 정리했는지 기록한다.
7. **처리 대장 기입** — `wiki/.ingest-ledger.tsv`에 한 줄 추가한다: `1_수집자료실경로 → 판정(새페이지/기존페이지에 흡수/보류) → 정착 페이지 → 날짜`. 보류(skip)한 파일은 사유와 해소 조건도 적는다.

한글(hwp)·PDF 등 md가 아닌 파일은 `tools/`의 변환 도구로 먼저 md로 바꾼 뒤 같은 절차를 적용한다.

### 2. 질문하기 (Query) — 트리거: 모든 질문

1. `wiki/index.md`와 위키 페이지를 탐색한다.
2. 위키 내용을 근거로 답하고, **근거 페이지 이름을 명시**한다.
3. 위키에 없는 내용이면 "위키에 해당 내용이 없습니다"라고 분명히 말한다. 아는 척하지 않는다.
   단, 거기서 끝내지 않고 **한 번 더 찾아본다**: `1_수집자료실/`(아직 정리 안 된 원자료 포함)를 파일명·제목으로 1회 검색하고, (법령 검색 도구를 설치했다면) 법령 원문도 조회한다. 발견하면 **"위키가 아닌 원자료 근거"임을 밝히고** 답한 뒤 "📌 위키에 정리할까요?"라고 제안한다.
4. 대화 중 남길 가치가 있는 지식·노하우가 만들어지면 답변 끝에 **"📌 위키에 남길까요?"** 라고 제안한다.
   사용자가 좋다고 하면 그때만 위키 페이지로 저장한다 (강제 저장 금지).

### 3. 건강검진 (Audit) — 트리거: "건강검진" / "점검해줘"

1. **미처리 자료** — 처리 대장(`wiki/.ingest-ledger.tsv`)과 `1_수집자료실/`을 대조해 정리 안 된 파일을 먼저 정리(Ingest)한다. 보류(skip) 항목은 매 검진마다 한 줄씩 재보고한다 (말없이 영영 미루지 않기).
2. **깨진 링크** — 존재하지 않는 페이지를 가리키는 `[[위키링크]]`를 찾는다.
3. **고아 페이지** — `index.md`에 등재되지 않은 위키 페이지 + 링크가 하나도 없는 외딴 페이지를 찾는다.
4. **index 정합** — `index.md` 목록과 실제 `wiki/` 파일이 일치하는지 확인한다.
5. **내용 모순** — 같은 주제를 다루는 페이지끼리 서로 다르게 기술한 곳을 찾는다 (원칙 7).
6. **페이지 규격** — 맨 앞 `> **핵심**` 콜아웃이 빠진 페이지를 찾는다.
7. **연결 기회** — 아직 링크되지 않았지만 연결하면 좋을 페이지 쌍을 제안하고, **분야를 넘는 연결이 전체 링크에서 차지하는 비율**도 함께 보고한다 (이 비율이 오르는 게 지식창고가 좋아지는 신호다).

결과를 요약 보고하고, 수정은 사용자 확인 후 반영한다. 이번에 다 못 한 항목은 `wiki/log.md`에 **「건강검진 이월 과제」 체크리스트 블록**으로 남겨 다음 검진 때 맨 먼저 회수한다.

## 위키 페이지 작성 규칙

- **콜아웃 3줄 (모든 페이지 맨 앞, 예외 없음)**:

  ```markdown
  > **핵심**
  > - 이 지식의 실무적 의미
  > - 다른 영역과의 연결 가능성
  > - 놓치기 쉬운 포인트
  ```

- **교차참조**: 관련 페이지를 `[[위키링크]]`로 적극 연결한다. 같은 분야 안의 연결보다
  **분야를 넘는 연결**을 우선하고, 연결 이유를 한 줄 적는다
  (예: `관련: [[식품위생법_영업허가]] — 같은 신고·허가 절차 구조`).
- **표 재구조화**: 별표·목록 같은 표 데이터는 원문 번호 리스트를 그대로 붙여넣지 말고,
  유형별·의미 단위의 표로 다시 짠다.
- **파일명**: 한글 또는 영문, 공백 대신 언더바(_), 확장자 `.md`
  (예: `식품위생법_영업허가.md`, `계약서_검토_체크리스트.md`).

## 지켜야 할 원칙 (12가지)

1. `1_수집자료실/`의 원본은 절대 수정하지 않는다 (읽기 전용).
2. `wiki/`가 단일 진실 공급원(SSOT)이다 — 지식 축적·편집은 위키 한곳에서만 한다.
   (SSOT = Single Source of Truth, "진짜 내용은 여기 하나"라는 뜻)
3. 모든 wiki 페이지 맨 앞에 `> **핵심**` 콜아웃 3줄을 넣는다.
4. 자료를 정리할 때마다 `index.md`와 `log.md`를 반드시 함께 갱신한다.
5. **의뢰인 실명·개인정보는 wiki에 절대 넣지 않는다.** `2_수임업무철/`은 격리 구역이며,
   노하우만 익명화("한 의뢰인의 경우") 후 위키에 반영한다.
6. 교차참조 `[[위키링크]]`를 적극적으로, 특히 분야를 넘어서 연결한다.
7. 위키 페이지 간 내용 모순이 발견되면 즉시 보고한다.
8. 정정할 때는 "이전엔 틀렸다" 같은 메타 언급 없이 정확한 내용만 남긴다.
9. 헌법(이 파일)의 변경은 사용자가 명시적으로 지시할 때만 한다.
   "기록해줘"라는 요청은 어떤 경우에도 `wiki/log.md`만 갱신한다.
10. 대화 중 가치 있는 지식을 발견하면 "📌 위키에 남길까요?"라고 제안한다 (강제 저장 금지).
11. 사용자의 피드백·스타일은 `memory/`에 축적하고 `MEMORY.md`에 한 줄 색인한다.
12. 세 가지 동작의 트리거: "자료 넣었어" = 정리(Ingest) / 질문 = 위키 근거 답변(Query,
    근거 페이지 명시·없으면 없다고) / "건강검진" = 점검(깨진 링크·고아 페이지·index 정합·내용 모순·연결 기회).

## 기억 노트 운영 (memory/)

- 사용자가 **"기억해줘"** / "다음부터 이렇게 해줘" / "이건 내 스타일이야"라고 말하면:
  1. `memory/`에 주제별 노트 파일을 만들거나 보강한다 (한 주제 = 한 파일).
  2. `memory/MEMORY.md`에 한 줄 색인을 추가한다 (파일명 + 요지, 200자 이내).
- 대화는 지나가면 사라지지만 `memory/`는 남는다. 피드백을 받으면 그 자리에서 기록한다.
- 다음 대화에서 관련 작업을 할 때 `MEMORY.md` 색인을 보고 필요한 노트만 찾아 읽는다.
- 지식(법령·노하우)은 `wiki/`에, 스타일·피드백·개인 규칙은 `memory/`에 — 섞지 않는다.

## 2_수임업무철 격리 규칙

- `2_수임업무철/`의 의뢰인 원본은 절대 수정·이동·삭제하지 않는다.
- 실명·회사명·연락처·주소·사건번호 등 개인정보는 wiki에 한 글자도 옮기지 않는다.
- 사건에서 배운 일반화 가능한 노하우만, 사용자가 요청할 때, "한 의뢰인의 경우" 식으로
  익명화해서 wiki에 남긴다.
- 백업하거나 남과 공유할 때 `2_수임업무철/`은 반드시 제외한다 (`2_수임업무철_안내.md` 참조).
