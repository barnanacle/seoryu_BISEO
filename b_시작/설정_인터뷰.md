# 설정 인터뷰 — 나만의 AI 비서 맞춤 질문지

> **보관 문서**: 과거 구축 설계에 사용한 질문지입니다. 현재 설치에는 사용하지 않으며, 설치 정본은 루트 `설치프롬프트.md`입니다.

지식창고를 만들 때 AI가 아래 12문항을 물어봅니다. 3개 파트로 나눠, 한 번에 4문항 이하씩 묻습니다. 답이 바로 떠오르지 않아도 괜찮습니다 — 굵게 표시된 **기본값**을 고르면 됩니다.

**AI에게**: 이 문항집은 이전 설계 참고용이다. 현재 운영 프로젝트에서는 `AGENTS.md`, `README.md`, `memory/`의 지침을 우선한다.

---

## 파트 1. 나에 대해 (4문항)

**1. 성함과 직함이 어떻게 되세요?**
- 왜 묻나: 보고서·문서에서 어떻게 표기하고 불러드릴지 정하기 위해서입니다.
- 답 예시: "홍길동, 행정사입니다"

**2. 전문분야는 무엇인가요?**
- 고르거나 직접 적으세요: 인허가 · 출입국 · 계약 · 행정심판 · 기타
- 왜 묻나: wiki(지식 창고)의 분야 카테고리를 전문분야에 맞게 짜기 위해서입니다.
- 답 예시: "인허가요. 화장품 쪽이 많아요"

**3. 가장 자주 하시는 업무 3가지를 알려주세요.**
- 왜 묻나: AI가 어떤 일을 우선적으로 도울지 기준이 됩니다.
- 답 예시: "화장품 인허가, 계약서 검토, 행정심판 청구서 작성"

**4. 주로 다루시는 자료는 어떤 종류인가요?**
- 고르거나 직접 적으세요 (여러 개 가능): 한글(HWP) · PDF · 스캔 이미지 · 엑셀 · 웹 자료
- 왜 묻나: 자료 상자(1_자료실) 폴더를 어떻게 나누고, 어떤 변환 도구를 먼저 챙길지 정합니다.
- 답 예시: "한글 서식하고 PDF 공문이 대부분이에요"

## 파트 2. 비서 성격 만들기 (4문항)

**5. 비서 이름을 무엇으로 할까요?**
- 보기: **JARVIS (기본)** / 직접 짓기 (예: 김비서, 나비)
- 왜 묻나: 부르기 편한 이름이 있으면 대화가 훨씬 자연스러워집니다. (지식창고 폴더 이름과는 별개입니다 — 폴더 이름은 9번에서 정합니다.)
- 답 예시: "JARVIS 그대로 할게요"

**6. 말투는 어떤 게 편하세요?**
- 보기: **정중한 존댓말 (기본)** / 친근한 존댓말 / 간결체
- 왜 묻나: 매일 쓰는 도구라, 듣기 편한 말투가 중요합니다.
- 답 예시: "친근한 존댓말이요"

**7. 보고는 어떤 스타일이 좋으세요?**
- 보기: **핵심 요약 먼저 (기본)** / 차근차근 상세
- 왜 묻나: 결론부터 들을지, 과정부터 들을지 — 일하시는 리듬에 맞추기 위해서입니다.
- 답 예시: "핵심 먼저 주세요"

**8. 제안은 얼마나 적극적으로 할까요?**
- 보기: **먼저 제안해줘 (기본)** / 물어볼 때만
- 왜 묻나: "이것도 정리해 둘까요?" 같은 선제 제안을 반기실지 정합니다.
- 답 예시: "먼저 제안해 주세요"

## 파트 3. 운영 규칙 맞춤 (4문항)

**9. 지식창고를 어디에 만들까요?**
- 기본: **홈 폴더 아래 `JARVIS`** (홈 폴더 = 내 컴퓨터에서 내 계정의 개인 폴더. Mac은 `/Users/<사용자이름>/JARVIS`, Windows는 `C:\Users\<사용자이름>\JARVIS`)
- 왜 묻나: AI가 파일을 만들고 관리할 위치를 확정해야 합니다.
- 답 예시: "기본으로 해주세요"

**10. wiki 분야 카테고리를 확인해 주세요.**
- 진행 방식: 앞의 2·3번 답을 바탕으로 AI가 카테고리 안을 먼저 제안합니다. 보시고 "좋아요" 하시거나, 고치고 싶은 부분만 말씀하시면 됩니다.
- 왜 묻나: 지식 전체 목차(wiki/index.md)의 뼈대가 됩니다.
- 답 예시: "인허가 / 계약 / 민원·행정심판 / 실무노하우 / 기타 관심분야 — 좋아요"

**11. 의뢰인 자료 취급 원칙을 확인해 주세요. (필수)**
- 원칙: 의뢰인 사건 자료는 「2_업무철」 폴더에만 격리 보관하고, **의뢰인 실명·개인정보는 wiki에 절대 넣지 않습니다.** 노하우만 익명화("한 의뢰인의 경우")해서 남깁니다.
- 왜 묻나: 개인정보 사고를 구조적으로 막는 가장 중요한 안전장치라서, 반드시 동의를 확인합니다.
- 답 예시: "동의합니다"

**12. 백업은 어떻게 할까요?**
- 보기: GitHub Private 저장소 (권장) / **나중에 정하기 (기본)**
  - GitHub = 파일을 인터넷 금고에 복사해 두는 무료 서비스. Private(비공개)로 만들면 나만 볼 수 있습니다.
- 왜 묻나: 컴퓨터 고장·분실에도 지식창고를 통째로 지키기 위해서입니다. 나중에 하셔도 됩니다 — 방법은 `e_확장/GitHub_백업.md`에 있습니다.
- 답 예시: "나중에 할게요"

---

모르겠으면 전부 기본값으로 시작해도 됩니다 — 나중에 "기억해줘"로 언제든 바꿀 수 있습니다. (단, 11번 의뢰인 자료 원칙만은 꼭 확인해 주세요.)
