# 반복 서식 구현 지침

이 문서는 새 법정 서식에도 같은 흐름을 구현하기 위한 기준이다. 실제 사건 자료나 완성본을 예시로 복사하지 않는다.

## 1. 권장 프로젝트 구조

```text
사건폴더/
├─ AGENTS.md                         사건별 출처·보안·완료 기준
├─ 받은자료/                          기관 원문과 상담기록, 읽기 전용
├─ 서식/
│  ├─ 법정서식_공식원본.pdf           현재 시행 중인 빈 원본
│  ├─ 법정서식_배경.png               벡터 합치기 실패 때만 쓰는 대체본
│  ├─ 별지_템플릿.html                제출용 PDF의 별지 레이아웃
│  ├─ 별지_템플릿.docx                편집용 별지 레이아웃
│  └─ 참고_형식.pdf                   문체·구조만 참고할 익명 자료
├─ bin/
│  ├─ build_pdf.py                   fields.json으로 결과 생성
│  └─ _vendor/                       꼭 필요한 동봉 라이브러리만
├─ 산출/
│  ├─ fields.json                    이번 사건의 유일한 입력값 원본
│  └─ _tmp/                          렌더·추출 등 중간 파일
└─ 옵션_한글파일/                    명시적으로 요청받을 때만 사용
```

원본과 결과를 분리한다. 스킬, 공개 저장소, 공용 템플릿에는 `받은자료/`, `산출/`, 실제 참고본을 포함하지 않는다.

## 2. 한 입력값으로 세 결과 만들기

`산출/fields.json`을 단일 기준으로 삼는다.

- 법정 서식 PDF: PDF 안에 `{{ }}`를 넣는 것이 아니라, 필드 키와 좌표를 빌더의 매핑표로 연결한다.
- 제출용 별지 PDF: HTML 템플릿의 `{{필드명}}`을 치환한 뒤 브라우저 인쇄로 만든다.
- 편집용 별지 DOCX: DOCX 템플릿의 같은 `{{필드명}}`을 치환한다.
- 최종 PDF: 값이 얹힌 법정 서식 1쪽 뒤에 별지 PDF의 모든 페이지를 순서대로 붙인다.

페이지 수는 결과 내용에 따라 달라진다. “항상 3쪽”처럼 고정하지 않는다.

## 3. 필드 정의 예시

법정 서식 계열의 예시는 다음과 같다.

```text
의견제출인_성명
의견제출인_주소
의견제출인_전화번호
처분의_제목
당사자_명칭
당사자_주소
당사자_전화번호
의견
기타
작성일
의견제출인_서명
수신
```

별지 계열의 예시는 다음과 같다.

```text
의견제출인_명칭
의견제출인_주소
처분청
건명
해당_품목
취지
소명1_제목
소명1_본문
소명2_제목
소명2_본문
소명3_제목
소명3_본문
소명4_제목
소명4_본문
결어
소명자료_목록
작성일
대표자
파일명
```

실제 키는 해당 프로젝트의 템플릿과 `python3 bin/build_pdf.py --keys` 출력이 우선한다. 모든 JSON 값은 문자열이어야 한다. `취지`, 각 소명 본문, `결어`, `소명자료_목록`처럼 긴 값은 빈 줄로 문단을 나눈다.

## 4. 빌더 구현 계약

새 서식에 맞는 빌더는 다음을 만족해야 한다.

1. 공식 서식 PDF를 다시 그리지 않고 첫 페이지 배경으로 그대로 보존한다.
2. 투명 A4 오버레이를 만들어 고정 좌표에 값만 배치한다.
3. PDF 라이브러리로 공식 원본과 오버레이를 합쳐 벡터 원본을 유지한다.
4. 벡터 합치기를 할 수 없을 때만 고해상도 배경 이미지로 대체하고, 실행 결과에 대체 사실을 표시한다.
5. 별지 HTML과 DOCX가 같은 필드명·문단 구조·여백·글꼴 체계를 사용하게 한다.
6. DOCX 본문형 값의 빈 줄을 실제 문단으로 변환한다.
7. 누락 필드는 `【확인 필요】`로 남기고 이름을 실행 결과에 표시한다.
8. 파일명에 사용할 수 없는 문자를 제거한다.
9. 최종 PDF, 편집용 DOCX, `fields.json`은 `산출/`에 두고 중간 파일은 `산출/_tmp/` 안에서만 다룬다.
10. `--keys`로 현재 필드 목록을 출력하고, `--no-open`으로 자동 열기를 끌 수 있게 한다.

공식 서식이 바뀌면 먼저 시행 상태와 페이지 크기를 확인하고, 좌표 매핑과 렌더 검사를 다시 한다. 과거 좌표를 새 서식에 그대로 쓰지 않는다.

## 5. 안전한 실행 순서

```text
1) 원문 전체 읽기
2) 법령명·조문·별표만 외부 법령 도구로 확인
3) build_pdf.py --keys로 필드 확정
4) 출처를 대조해 fields.json 작성
5) 누락·충돌 항목 확인
6) --no-open으로 1차 생성
7) PDF와 DOCX 렌더·구조 검사
8) 필요하면 보정 후 재생성
9) 행정사 최종 검토
```

사용자가 정한 업무 방향을 AI가 바꾸지 않는다. 근거 없는 사실, 실제로 없는 첨부자료, 임의의 오늘 날짜를 넣지 않는다.

## 6. 공개 전 개인정보 점검

공개 또는 커밋 가능한 항목:

- 일반화한 `SKILL.md`와 구현 지침
- 필드명 목록과 빈 JSON 예시
- 개인정보 없는 빈 템플릿
- 범용 빌더와 검사 코드

공개 또는 커밋하면 안 되는 항목:

- 실제 `fields.json`
- 기관 통지서, 상담기록, 녹취, 계약서, 증빙
- 업체명·개인명·주소·전화번호·등록번호·문서번호가 남은 참고본
- 사건명이 들어간 PDF·DOCX·HWP·HWPX
- 렌더 이미지, 추출 텍스트, 로그, 임시 폴더

## 7. 완료 점검표

- [ ] 공식 서식은 현행 빈 원본이며 원본 파일을 수정하지 않았다.
- [ ] 법정 서식과 별지가 하나의 `fields.json`을 사용한다.
- [ ] 모든 JSON 값은 문자열이다.
- [ ] 공식 서식 첫 페이지의 벡터·고정 문구·선이 유지되었다.
- [ ] 별지 PDF와 편집용 DOCX의 제목·문단·날짜·서명 배치가 대응한다.
- [ ] 남은 `{{필드명}}`과 `【확인 필요】`를 확인했다.
- [ ] 글자 겹침·잘림·빈 페이지·페이지 크기를 렌더링으로 검사했다.
- [ ] 외부 법령 조회에 사건 식별정보를 보내지 않았다.
- [ ] 공개 저장소와 스킬에 실제 사건 자료가 없다.
- [ ] 행정사가 최종 검토하기 전에는 완성본으로 표시하지 않았다.
