# GitHub 백업 — 지식창고를 잃지 않는 법

> **이 문서는 언제 보나**: 지식창고를 어느 정도 쓰기 시작한 뒤, "PC가 고장 나면 이걸 다 잃는 건가?" 하는 걱정이 들 때 봅니다. 필수는 아니지만 강력히 권장합니다.

> **⚠️ 이 문서는 설치 안내가 아닙니다.**
> 현재 설치는 루트 `설치프롬프트.md`를 Codex에 붙여넣는 방법만 사용합니다. 이 문서는 설치가 끝난 **내 JARVIS 운영 폴더**를 별도의 비공개 저장소에 백업하는 선택 안내입니다.

## 1. 왜 백업이 필요한가요

지식창고는 전부 내 PC 안의 파일입니다. PC가 고장 나거나 분실되면 그동안 쌓은 지식이 통째로 사라집니다.

GitHub에 올려두면 세 가지가 해결됩니다.

1. **소실 방지** — PC가 고장 나도 인터넷에 사본이 남습니다.
2. **이력 보존** — 언제 무엇을 바꿨는지 기록이 남고, 실수로 지운 내용도 되돌릴 수 있습니다.
3. **다중 PC** — 사무실 PC와 집 PC에서 같은 지식창고를 이어서 쓸 수 있습니다.

처음 나오는 용어를 한 줄씩 풀면 이렇습니다.

| 용어 | 한 줄 풀이 |
|---|---|
| GitHub(깃허브) | 파일과 변경 이력을 보관해 주는 인터넷 저장소 서비스. 무료로 시작할 수 있습니다 |
| 리포지토리(repository) | 깃허브에 만드는 보관함 하나. 지식창고 폴더 전체를 보관함 하나로 만듭니다 |
| 커밋(commit) | "여기까지 저장" 도장을 찍는 일 |
| 푸시(push) | 도장 찍은 내용을 인터넷 저장소로 올리는 일 |
| 클론(clone) | 인터넷 저장소의 내용을 다른 PC로 통째로 내려받는 일 |

터미널(까만 명령어 창)은 쓰지 않습니다. **GitHub Desktop**이라는 앱에서 전부 마우스 클릭으로 합니다.

## 2. 준비 — 가입과 앱 설치

Codex 설치에는 GitHub 계정이 필요하지 않습니다. 아래 계정과 GitHub Desktop은 개인 JARVIS 운영 폴더를 백업하기로 선택한 경우에만 준비합니다.

### 2-1. GitHub 가입

1. 브라우저에서 `https://github.com` 접속
2. **Sign up** 클릭 → 이메일·비밀번호·아이디 입력
3. 이메일로 온 인증 코드를 입력하면 가입 완료

✅ 이렇게 되면 성공: github.com 화면 오른쪽 위에 내 프로필 동그라미가 보입니다.

### 2-2. GitHub Desktop 앱 설치

1. 브라우저에서 `https://desktop.github.com` 접속 → **Download** 클릭
2. 설치 방법은 Mac과 Windows가 조금 다릅니다.

| 구분 | Mac | Windows |
|---|---|---|
| 내려받는 파일 | 압축(zip) 파일 | 설치 파일(exe) |
| 설치 | 압축을 풀고 나온 GitHub Desktop 아이콘을 **응용 프로그램** 폴더로 드래그 | 내려받은 파일을 더블클릭하면 자동으로 설치됩니다 |

3. 처음 실행하면 **Sign in to GitHub.com** 버튼이 보입니다 → 클릭 → 방금 만든 계정으로 로그인 → 브라우저에 **Authorize**(허용) 버튼이 나오면 클릭

✅ 이렇게 되면 성공: GitHub Desktop 첫 화면이 열리고, 설정 메뉴(Mac: Settings/Preferences, Windows: Options)의 **Accounts**에 내 아이디가 보입니다.

실패 시: 앱을 완전히 종료했다가 다시 실행해 보세요. 그래도 안 되면 `3_사용법/FAQ_문제해결.md`를 보거나, AI에게 화면에 보이는 문구를 그대로 알려주며 물어보세요.

## 3. 지식창고 폴더를 리포지토리로 만들기

⚠️ **순서가 중요합니다.** 리포지토리를 만든 직후, **커밋(저장 도장)을 찍기 전에** 반드시 4번(.gitignore)을 먼저 설정하세요. 한 번이라도 커밋에 들어간 파일은 이력에 계속 남기 때문입니다.

1. GitHub Desktop 메뉴 → **File → Add Local Repository**(로컬 저장소 추가)
2. **Choose…** 클릭 → 내 지식창고 폴더(기본 이름 JARVIS) 선택
3. "This directory does not appear to be a Git repository"(아직 저장소가 아닙니다) 안내가 나오면 → 파란 글씨 **create a repository** 클릭
4. 만들기 창에서 이렇게 두고 진행합니다.
   - **Name**: 폴더 이름 그대로
   - **Git ignore**: None 그대로 (다음 단계에서 직접 만듭니다)
   - **License**: None 그대로
   - **Create Repository** 클릭
5. 왼쪽 **Changes** 탭에 지식창고 파일들이 나타납니다. **아직 Commit 버튼을 누르지 마세요.** 먼저 아래 4번으로 갑니다.

✅ 이렇게 되면 성공: 앱 왼쪽 위에 내 지식창고 이름이 표시되고, Changes 탭에 파일 목록이 보입니다.

## 4. .gitignore — 올리면 안 되는 것 빼기 (필수)

**.gitignore(깃이그노어)**: "이 목록의 파일·폴더는 올리지 마라"라는 제외 명단 파일입니다.

왜 필수인가: `서류함/`에는 의뢰인 실명 자료가 있습니다. 뒤 단계에서 저장소를 비공개(Private)로 만들지만, **비공개라 하더라도 의뢰인 원본은 인터넷에 올리지 않는 것이 원칙**입니다. 계정 해킹, 실수로 공개 전환 같은 위험을 처음부터 차단하기 위해서입니다.

### 방법 A — AI에게 시키기 (권장)

AI에게 이렇게 말하세요:

```
지식창고 맨 위에 .gitignore 파일을 만들어 줘. 내용은 아래 그대로:

# 의뢰인 사건 자료 — 인터넷에 올리지 않음 (원칙)
서류함/

# DATA 안에 의뢰인 식별 원본이 있다면 그 하위 폴더도 여기에 추가
# (아래는 예시 — 실제 폴더명으로 바꿔 쓰세요)
# DATA/의뢰인원본/

# 시스템 부산물
.DS_Store
Thumbs.db
```

### 방법 B — GitHub Desktop에서 직접

1. 메뉴 **Repository → Repository Settings…** → **Ignored Files** 탭
2. 위 블록의 `# 의뢰인…`부터 `Thumbs.db`까지 붙여넣기 → **Save**

✅ 이렇게 되면 성공: 왼쪽 Changes 목록에서 `서류함/` 안의 파일들이 사라집니다. (지워진 게 아니라 "올리지 않기로" 된 것입니다 — 내 PC에는 그대로 있습니다.)

⚠️ `DATA/` 안에도 의뢰인 이름이 들어간 원본 파일이 있다면, 그 폴더명을 위 명단에 한 줄 추가하세요. 있는지 애매하면 AI에게 이렇게 말하세요: "DATA 폴더 안에 의뢰인 실명이나 개인정보가 든 파일이 있는지 훑어보고 알려줘."

## 5. 첫 커밋과 비공개 업로드 (Publish)

1. 왼쪽 아래 **Summary** 칸에 한 줄 메모 입력 (예: `지식창고 첫 백업`)
2. **Commit to main** 클릭
3. 화면 위쪽의 **Publish repository** 클릭
4. 뜨는 창에서 **"Keep this code private" 체크가 켜져 있는지 반드시 확인하세요.** 이 체크가 비공개(Private) 설정입니다. 꺼져 있으면 켭니다.
5. **Publish Repository** 클릭

✅ 이렇게 되면 성공: 브라우저에서 github.com 로그인 → 내 프로필 → Repositories에 지식창고 이름이 보이고, 이름 옆에 **Private** 표시가 붙어 있습니다.

실패 시: Private 표시가 없다면(공개로 올라갔다면) 즉시 github.com의 해당 저장소 → **Settings** → 맨 아래 **Danger Zone** → "Change repository visibility"에서 Private로 바꾸세요. 어려우면 AI에게 화면 문구를 보여주며 물어보세요. (`3_사용법/FAQ_문제해결.md`)

## 6. 평소 백업 절차 — 커밋 → 푸시

이후의 백업은 매번 이 세 번의 클릭이 전부입니다.

1. GitHub Desktop 실행 → 왼쪽 **Changes**에 그동안 바뀐 파일 목록이 보입니다
2. **Summary**에 한 줄 메모 (예: `이번 주 위키 정리`) → **Commit to main** 클릭
3. 오른쪽 위 **Push origin** 클릭

✅ 이렇게 되면 성공: Push origin 버튼이 **Fetch origin**으로 바뀌고, 화살표 옆 숫자가 사라집니다.

실패 시: 인터넷 연결을 확인한 뒤 Push origin을 다시 누르고, 그래도 안 되면 오류 문구를 AI에게 그대로 보여주세요. (`3_사용법/FAQ_문제해결.md`)

## 7. 다른 PC에서 이어쓰기 (클론)

1. 새 PC에도 GitHub Desktop을 설치하고 **같은 계정**으로 로그인합니다 (위 2번과 동일)
2. **File → Clone Repository** → 목록에서 **내 지식창고 이름**을 선택 → 저장 위치 선택(홈 폴더 권장) → **Clone**
3. 복원된 내 JARVIS 폴더를 Codex 프로젝트로 엽니다. 운영 파일이 빠졌다면 루트 `설치프롬프트.md`를 같은 프로젝트에 한 번 붙여넣어 누락된 파일만 보완합니다.
4. 두 PC를 오갈 때는 규칙 하나만 기억하세요.
   - **작업 시작 전**: **Fetch origin** → **Pull**(내려받기)
   - **작업 끝난 후**: **Commit** → **Push**(올리기)
   - 이 순서만 지키면 두 PC의 내용이 어긋나지 않습니다.

참고: `서류함/`은 4번에서 제외했으므로 다른 PC로 자동 전달되지 않습니다. 이것은 의도된 동작입니다 — 의뢰인 원본이 필요하면 인터넷을 거치지 않는 별도 수단(암호를 건 이동식 저장장치 등)으로 옮기세요.

## 8. 백업 주기

- **기본: 주 1회.** 요일을 정해 두면 잊지 않습니다 (예: 금요일 퇴근 전 3클릭).
- **추가: 큰 정리를 한 직후.** 자료를 많이 넣어 정리했거나 "건강검진"을 돌린 날은 그날 바로 백업하세요.
- 백업할 게 있는지 궁금하면 GitHub Desktop을 열어 보세요 — **Changes**에 파일이 쌓여 있으면 백업할 때가 된 것입니다.
