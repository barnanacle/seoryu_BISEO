## 위키 페이지 작성 규칙

- **콜아웃 3줄 (모든 페이지 맨 앞, 예외 없음)**:

  ```markdown
  > **핵심**
  > - 이 지식의 실무적 의미
  > - 다른 영역과의 연결 가능성
  > - 놓치기 쉬운 포인트
  ```

- **교차참조**: 관련 페이지를 `[[위키링크]]`로 적극 연결한다. 같은 분야 안의 연결보다 **분야를 넘는 연결**을 우선하고, 연결 이유를 한 줄 적는다 (예: `관련: [[식품위생법_영업허가]] — 같은 신고·허가 절차 구조`).
- **표 재구조화**: 별표·목록 같은 표 데이터는 원문 번호 리스트를 그대로 붙여넣지 말고, 유형별·의미 단위의 표로 다시 짠다.
- **파일명**: 한글 또는 영문, 공백 대신 언더바(_), 확장자 `.md`. **특수문자·이모지는 쓰지 않는다.**
  (예: `식품위생법_영업허가.md`, `인허가_영업신고_허브.md`)

## 영역별 인덱스 규약 (wiki/index.md)

`wiki/index.md`는 이 창고의 유일한 최상위 목차다. 아래 서식을 **문자 그대로** 지킨다.

1. 카테고리 헤더는 `## <카테고리명>` 한 줄 (`##` 고정, 장식 문자·이모지 금지)
2. 헤더 바로 아래 `> 여기엔 무엇이 있나: …` 한 줄
3. 페이지는 `- [[페이지명]] — 한 줄 요지` (하이픈+공백으로 시작, 구분자는 `—`)
4. 각 카테고리의 첫 페이지 줄은 허브: `- [[<카테고리>_허브]] — 이 영역의 관문`
   허브 파일명은 카테고리명에서 **공백은 지우고, 가운뎃점(·)은 언더바(_)로** 바꿔 만든다 (「실무 노하우」 → `실무노하우_허브.md` · 「비자·출입국」 → `비자_출입국_허브.md`). 만든 파일 이름은 `index.md`의 `[[…]]` 표기와 **글자 그대로 같아야 한다.**

**읽는 순서**: 카테고리 헤더만 → 해당 카테고리 섹션만 → 허브 → 페이지 본문. 목차 전체를 통째로 읽지 않는다.
**허브의 역할**: 카테고리마다 허브 페이지 한 장을 두고, 새 페이지는 최소한 허브와 서로 링크한다. 그러면 아무와도 이어지지 않은 외딴 페이지가 애초에 생기지 않는다 (나중에 찾아 고치는 것보다 싸다).
**카테고리 조정**: 기본 7개는 예시다 — 사용자가 "카테고리 바꿔 줘"라고 하면 `index.md`·허브·`1_자료실/` 분야 폴더를 한 세트로 함께 바꾼다.

> `wiki/index.md`의 서식(`## 카테고리` / `- [[페이지명]] — 요지`)과 `wiki/.ingest-ledger.tsv`의 4컬럼·탭 구조가 곧 대시보드의 입력 규격입니다. **이 서식을 바꾸면 대시보드가 숫자를 세지 못합니다.**

## 자료 폴더와 카테고리

- `1_자료실/` 하위 폴더는 `wiki/index.md`의 카테고리와 **같은 이름으로, 카테고리 수만큼** 둔다 (예: 카테고리 「비자·출입국」 ↔ `1_자료실/비자·출입국/`). 자료가 아직 없는 카테고리는 빈 폴더로 둔다. 그러면 "이 자료는 어느 영역인가"가 폴더 이름만으로 정해진다.
- `wiki/` 안은 하위 폴더 없이 평평하게 관리한다. 분류는 `wiki/index.md`가 담당한다. 허브 페이지도 평평한 한 장일 뿐이다.
- `2_서류철/`·`3_작업실/`은 기본 자동 정리(Ingest) 대상이 아니다. 다만 사용자가 파일·하위 폴더·전체 폴더를 명시해 환류를 지시한 경우에는 그 범위만 대상이 된다. `tools/`는 어떤 경우에도 자료 환류 대상이 아니다.
