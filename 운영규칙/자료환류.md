상위 AGENTS.md 색인에서 호출됨 · 안전 규칙은 상위가 우선

### 1. 자료 환류 (Ingest / Injection) — 트리거: "자료 넣었어" / "이거 정리해줘" / "wiki에 반영해" / "환류해" / "인젝션해"

`3_작업실/`·`2_서류철/`·`1_자료실/`가 정보를 쌓는 세 곳이고, 여기서 다시 쓸 지식만 골라 `wiki/`로 환류한다. 상시 감시하거나 자동으로 훑지 않는다. **사용자가 환류를 지시한 때만** 아래 절차가 시작된다.

1. **범위 확정**
   - "자료 넣었어"처럼 대상을 말하지 않은 기본 명령은 `1_자료실/` 전체를 대상으로 한다.
   - 특정 파일을 지목하면 그 파일만, `3_작업실`·`2_서류철`·`1_자료실` 중 폴더를 지목하면 그 폴더 아래를 재귀적으로 훑는다. 예: "3_작업실을 wiki에 반영해", "2_서류철 전체를 환류해", "1_자료실을 인젝션해".
   - 새 트리거만 말하고 대상이 없으면 어느 파일 또는 어느 폴더인지 한 번 묻는다. 임의로 세 폴더 전체를 열지 않는다.
   - `2_서류철/`을 지목한 경우 안전 2의 외부 전송 안내를 먼저 하고, 사용자가 명시한 범위 밖은 열지 않는다.
2. **미반영 자료 식별** — 지정 범위의 상대경로를 처리 대장 `wiki/.ingest-ledger.tsv`의 `자료경로`와 대조한다. 대장에 `새페이지` 또는 `기존페이지 흡수`로 기록된 경로는 이미 반영된 자료이므로 건너뛴다. `보류`는 사유와 해소 조건을 다시 확인한다. **대장에 없는 파일만 새로 판정**한다. 같은 파일을 내용 검색이나 파일명 추측으로 반복 판정하지 않는다.
   - 경로에 실명·상호가 있으면 정규화한 상대경로의 SHA-256 앞 12자를 `2_서류철/#sha256:<12자리>` 같은 **안전 식별자**로 대조·기록한다. 중복은 가리되 wiki에는 이름을 남기지 않는다.
   - 제외: `.gitkeep`·`.DS_Store`·숨김 파일, 각 폴더의 `안내.md`, 빈 파일, 임시 파일(`~$` 등), `tools/`·`wiki/`·`memory/`·설치 설명서.
   - 미반영 파일이 없으면 "검토 N건 / 이미 반영 N건 / 새 반영 0건"으로 보고하고 끝낸다.
3. **읽기** — 원본을 읽고 내용을 파악한다. 원본은 절대 고치지 않는다.
4. **가르기** — 출처별로 다음 원칙을 적용한 뒤, 위키로 갈 부분만 골라 **정착 판정 4문**과 안전 1의 게이트를 적용한다.
   - `1_자료실/`: 여러 사건에 공통으로 쓰는 공식·공개 근거를 구조화한다.
   - `3_작업실/`: 완성·검토 중 산출물에서 재사용 가능한 판단·서식·절차만 뽑는다. 문서 전체를 복사하지 않는다.
   - `2_서류철/`: 사건 고유 사실은 그대로 격리하고, 다른 사건에도 쓸 수 있는 노하우만 9종 개인정보를 지워 익명화한다. 한 항목이라도 남으면 저장을 멈추고 확인받는다.
5. **위키 페이지 생성** — `wiki/`에 새 페이지를 만든다. 맨 앞 `> **핵심**` 콜아웃 3줄 필수.
6. **교차연결** — 기존 위키를 훑어 관련 페이지와 양방향 `[[위키링크]]`를 건다.
   **새 페이지는 그 영역의 `<카테고리>_허브` 페이지와 반드시 서로 링크하고, 양방향 연결을 2개 이상(가급적 분야를 넘는 연결 1개 포함) 만들고 시작한다.** 못 채우면 연결 후보를 한 줄 제안하고 "연결 부족" 표시를 남긴다.
7. **index 등재** — `wiki/index.md`의 알맞은 카테고리에 아래 서식 그대로 한 줄 추가한다.
8. **log 기록 + 처리 대장 기입** — `wiki/log.md` 맨 위(오늘 날짜)에 무엇을 정리했는지 기록하고, `wiki/.ingest-ledger.tsv`에 파일마다 한 줄 추가한다: `자료경로 또는 안전 식별자 / 판정(새페이지·기존페이지 흡수·보류) / 정착페이지 / 날짜`. 보류는 사유와 해소 조건도 함께 적는다. 경로에는 실명·상호를 남기지 않는다.
9. **결과 보고** — `검토 N건 / 이미 반영 N건 / 새 페이지 N건 / 기존 페이지 보강 N건 / 보류 N건` 순서로 한 줄 요약하고, 새로 만들거나 보강한 위키 페이지 이름을 적는다.

md가 아닌 파일(한글·PDF 등)은 사용자가 내용을 붙여 넣어 주거나, 변환 도구가 있으면 md로 바꾼 뒤 같은 절차를 적용한다.

작업 전에 `운영규칙/위키작성.md`와 `운영규칙/상담수임.md`를 함께 읽어 위키 형식과 정착 판정을 적용한다.
