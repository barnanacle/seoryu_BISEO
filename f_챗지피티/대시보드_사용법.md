# 대시보드 사용법 — 내 지식이 얼마나 쌓였는지 눈으로 보기

> **이 문서는 언제 보나**: 지식이 얼마나 쌓였는지 눈으로 보고 싶을 때, 그리고 "무엇부터 손봐야 하나"가 궁금할 때 봅니다.

---

## 1. 이게 뭔가요 (30초)

지식창고가 커지면 이런 게 궁금해집니다.

- 지금까지 몇 페이지나 정리됐지?
- 아직 정리 안 한 자료가 얼마나 남았지?
- 어느 분야만 잔뜩 쌓이고 어느 분야는 비어 있나?

**대시보드**는 이걸 한 장의 화면으로 보여 주는 파일입니다. *대시보드: 자동차 계기판처럼, 상태를 한눈에 보여 주는 화면.*

지식창고 폴더 안에 `dashboard.html`이라는 파일이 하나 생기고, 그걸 **더블클릭**하면 평소 쓰는 인터넷 브라우저(크롬·사파리·엣지)에서 열립니다.

**만들어진 화면은 내 컴퓨터 안에만 있습니다.** 어디로도 정보를 보내지 않고, 인터넷 선을 뽑아도 똑같이 열립니다.
(다만 아래 2절 **길 ①**처럼 AI에게 시켜서 새로 그릴 때는 인터넷 연결과 요금제 사용량이 듭니다. **길 ②**로 직접 실행하면 그것도 들지 않습니다.)

---

## 2. 만드는 법 — 두 가지 길

### 길 ① AI에게 말로 시키기 (가장 간단)

AI에게 이렇게 말하세요.

```
대시보드 새로 그려줘
```

✅ **이렇게 되면 성공**: AI가 "대시보드를 새로 그렸습니다 — 위키 N쪽, 아직 정리 안 된 자료 N건…"처럼 요약을 알려 줍니다.

*AI가 이 말을 알아듣는 이유: 규칙서(`AGENTS.md`)의 「네 가지 동작」 중 4번에 이 절차가 적혀 있습니다. AI는 파이썬을 돌릴 수 있으면 돌리고, 못 돌리면 아래 5-2처럼 손으로 채웁니다.*

> ⚠️ **앱이 내 컴퓨터에서 프로그램(파이썬)을 실행할 수 있어야** 이 길이 온전히 동작합니다. 계정·버전에 따라 안 될 수 있고, 그때는 AI가 자동으로 5-2 방식(손으로 채우기)으로 넘어갑니다. 어느 쪽이 되는지는 강사가 확인해 알려 드립니다 → `실측_점검표.md` #8.

### 길 ② 직접 한 줄 실행하기

터미널(Mac) 또는 명령 프롬프트(Windows)를 열고, 지식창고 폴더에서 아래 한 줄을 붙여넣으세요.

**Mac**

```
cd ~/JARVIS
python3 tools/make_dashboard.py
```

**Windows**

```
cd %USERPROFILE%\JARVIS
python tools\make_dashboard.py
```

✅ **이렇게 되면 성공**: 아래처럼 나옵니다.

```
✅ 대시보드를 새로 그렸습니다.
   파일: /Users/홍길동/JARVIS/dashboard.html
   위키 7쪽 · 아직 정리 안 된 자료 3건 · 보류 1건 · 분야 횡단 연결 40%

👉 이제 지식창고 폴더의 dashboard.html 파일을 더블클릭해서 열어 보세요.
```

## 3. 보는 법

지식창고 폴더(기본: Mac `~/JARVIS`, Windows `C:\Users\<사용자>\JARVIS`)에서 **`dashboard.html`을 더블클릭**하세요. 그게 전부입니다.

- 브라우저 즐겨찾기에 넣어 두면 다음부터 클릭 한 번으로 열립니다.
- 화면을 종이로 남기고 싶으면 브라우저에서 인쇄(Ctrl+P / ⌘+P)하면 A4에 맞춰 나옵니다.

## 4. 왜 "새로 그려야" 하나요 (한 번만 이해하면 됩니다)

브라우저에는 **안전 규칙**이 있습니다. 내 컴퓨터에서 연 웹 화면이 내 폴더의 다른 파일을 마음대로 읽지 못하게 막아 둔 것입니다(악성 웹페이지가 내 파일을 훔쳐보는 걸 막는 장치입니다).

그래서 대시보드는 화면이 폴더를 뒤지는 방식이 아니라, **숫자를 미리 세어서 화면 파일 안에 적어 두는 방식**으로 만듭니다. 두 단계로 나뉘는 이유가 이것입니다.

1. (숫자 세기) `make_dashboard.py`가 지식창고를 훑어 숫자를 셉니다.
2. (보기) `dashboard.html`을 더블클릭해 그 숫자를 봅니다.

따라서 **화면에 보이는 숫자는 "새로 그린 시각" 기준의 사진**입니다. 자료를 더 넣었으면 다시 한 번 "대시보드 새로 그려줘"라고 하세요.

## 5. 파이썬이 없어도 됩니다 (Windows에서 흔합니다)

*파이썬(Python): 숫자를 세는 작은 프로그램을 돌리는 도구. 설치되어 있지 않은 컴퓨터도 많습니다.*

### 5-1. 먼저 있는지 확인

- **Mac**: 터미널을 열고 `python3 --version` → `Python 3.x.x`가 나오면 있는 것입니다.
- **Windows**: 명령 프롬프트를 열고 `python --version` (안 되면 `py --version`) → `Python 3.x.x`가 나오면 있는 것입니다.

`command not found` / `찾을 수 없습니다`가 나오면 없는 것입니다. **설치하지 않으셔도 됩니다.** 아래 5-2로 가세요.

### 5-2. 없을 때 — AI에게 대신 채워 달라고 하기

아래 문장을 그대로 복사해서 AI에게 보내세요.

```
파이썬이 없으니 네가 직접 대시보드 숫자를 채워줘.

1. 지식창고의 dashboard.html 파일에서 「const DATA = /*__DATA__*/ null;」 이 한 줄만 찾아라.
2. wiki/index.md, wiki/.ingest-ledger.tsv, wiki/log.md, memory 폴더, 1_자료실 폴더의 파일 목록을 읽고
   숫자를 세어, null 자리에 JSON 한 덩이를 넣어라. 형식은 f_챗지피티/대시보드_사용법.md 의 「부록」을 보라.
3. 지킬 것: /*__DATA__*/ 표시와 앞뒤 <script> 태그는 절대 지우지 마라.
   2_서류철 폴더는 절대 열지 마라. 1_자료실 폴더는 파일 이름만 보고 내용은 열지 마라.
   아래 9가지가 보이면 가려서 적어라 —
   사람 이름(외국인 성명 포함)·회사(상호)명·전화번호·사업자등록번호·접수(사건)번호·
   금액·주소·주민등록번호/여권번호·이메일.
   (김○○ · (주)○○ · 010-****-**** · ***-**-***** · 2026******* · ***원 ·
    ○○ 지역 · ******-******* · ***@***)
4. 다 되면 그 파일 하나만 저장하고, 무엇을 바꿨는지 한 줄로 알려 달라.
```

✅ **이렇게 되면 성공**: AI가 "숫자를 채웠습니다"라고 답하고, `dashboard.html`을 더블클릭하면 숫자가 보입니다.

## 6. 읽는 법 — 숫자 8가지와, 나쁠 때 할 일

| 보이는 것 | 뜻 | 나쁘면 무엇을 하나 |
|---|---|---|
| **정리된 위키 페이지** | 지금까지 쌓인 지식의 총량 | 늘지 않는다면 자료를 넣고 "자료 정리해줘" |
| **아직 정리 안 된 자료** | 1_자료실 폴더엔 있는데 아직 정리 안 된 파일 수 | 0에 가깝게 유지하세요 → "자료 정리해줘" |
| **보류 중인 자료** | "나중에 정하기"로 미뤄 둔 자료 (며칠째인지 함께 표시) | 30일 넘게 묵었다면 한 번 결정하세요 |
| **분야를 넘는 연결 비율** | 서로 다른 영역끼리 이어진 링크의 비율 | 낮으면 → "건강검진해줘"로 연결 후보 받기 |
| **영역별 분포** | 어느 영역에 몇 쪽이 쌓였는지 막대 | 한쪽만 길면, 비어 있는 영역 자료를 먼저 정리 |
| **최근 정리 10건** | 작업 일지에서 가져온 최신 기록 | 기록이 안 남으면 AI에게 "일지에도 남겨줘" |
| **연결이 부족한 페이지** | 연결이 2개 미만인 외딴 페이지 | → "건강검진해줘" 하면 이어 줄 후보를 제안합니다 |
| **기억 파일 상태** | 기억 3파일의 줄 수와 상한 | "상한 초과"가 뜨면 → "기억 정리해줘" |

그 밖에 **목차에 없는 페이지**(wiki 폴더엔 있는데 `index.md`에 등재 안 된 페이지)도 함께 보여 줍니다. 보이면 "목차에 넣어줘"라고 하세요.

**검색창**: 위쪽 검색창에 낱말을 넣으면(예: `계약`) 화면의 모든 목록이 그 낱말이 든 줄만 남습니다. 페이지가 많아졌을 때 유용합니다. 검색은 내 브라우저 안에서만 일어나고, 어디에도 전송되지 않습니다.

## 7. 대시보드가 읽는 것 · 절대 열지 않는 것

| | 대상 |
|---|---|
| **읽습니다** | `wiki/index.md` · `wiki/.ingest-ledger.tsv`(처리 대장) · `wiki/log.md` · `wiki/*.md`(파일 이름과 `[[링크]]`만) · `memory/` 3파일(줄 수·글자 수만) · `1_자료실/`(**파일 이름 목록만**) |
| **절대 열지 않습니다** | **`2_서류철/` 전체**(의뢰인 실명 자료) · `3_작업실/` · 1_자료실 파일의 **내용** |

`2_서류철/`은 경로조차 들여다보지 않습니다. 지식 지도(graphify)의 안전 규칙과 같습니다 — **인덱싱은 wiki 폴더만, 2_서류철과 1_자료실 내용은 제외.**

> ⚠️ **서식이 곧 규격입니다.**
> `wiki/index.md`의 서식(`## 카테고리` / `- [[페이지명]] — 요지`)과 `wiki/.ingest-ledger.tsv`의 4칸·탭 구조가 곧 대시보드의 입력 규격입니다. **이 서식을 바꾸면 대시보드가 숫자를 세지 못합니다.**

## 8. 민감정보는 가려서 보여 줍니다

대시보드에는 **파일 이름과 목차 문구**가 그대로 나옵니다. 그런데 파일 이름에 의뢰인 이름이 들어가는 일이 흔합니다(`홍길동_계약서.pdf`).

그래서 화면에 내보내기 전에 아래 표기를 자동으로 가립니다.

| 가리는 것 | 예 |
|---|---|
| 사람 이름으로 보이는 표기 | `홍길동_계약서.pdf` → `홍○○_계약서.pdf` |
| 외국인 성명 | `NGUYEN VAN A_비자연장.pdf` → `N○○○○○○○○○_…` · `王小明` → `王○○` |
| 회사·상호명 | `(주)예시상사_계약서.pdf` → `(주)○○_계약서.pdf` |
| 전화번호 | `010-1234-5678` → `010-****-****` |
| 사업자등록번호 | `123-45-67890` → `***-**-*****` |
| 주민등록번호 | `******-*******` |
| 여권번호 | `M12345678` → `M********` |
| 민원 접수번호 | `20260099999` → `2026*******` |
| 금액 | `2,750,000원` → `***원` |
| 주소 | `서울시 강남구 테헤란로 123` → `○○ 지역` |
| 이메일 | `***@***` |

가린 게 있으면 화면 맨 위에 **주황색 경고 배지**가 뜹니다. 이건 "고쳐라"는 신호입니다 — 그런 이름의 자료가 의뢰인 사건 자료라면 `2_서류철/`로 옮기고, 위키 쪽 파일 이름에서는 이름·번호를 빼 주세요. **행정사법 제23조(비밀엄수)** 때문에 지식창고에서 지켜야 할 습관입니다.

- 가리는 것은 **화면 표시뿐**입니다. 원래 파일은 손대지 않습니다.
- 사람 이름 추정은 완벽하지 않습니다. 이름이 아닌 낱말이 가려져 불편하면, 실행할 때 뒤에 `--no-name-guess`를 붙이면 이름 추정만 끕니다(번호·금액은 계속 가립니다).
  예: `python3 tools/make_dashboard.py --no-name-guess`

> ⚠️ **가림은 완전하지 않습니다.** 규칙에 없는 형태(흔치 않은 상호 표기·번지 없는 주소·성씨 목록에 없는 이름 등)는 **그대로 지나갑니다.**
> **화면에 가려지지 않았다는 것이 "안전하다"는 뜻은 아닙니다.** 주황색 배지가 없어도 이 파일은 **어떤 경우에도 공개하지 않습니다**(아래 9절).
> 반대로 이름이 아닌 낱말이 가려지는 일(과하게 가림)도 생깁니다 — 그건 그냥 두셔도 됩니다.

### 위키에 남은 개인정보를 한 번에 찾고 싶다면

현황판은 **화면에 보일 때만** 가립니다. 파일 안에 남은 것 자체를 찾으려면 같은 규칙으로 도는 점검 도구를 쓰세요.

```
python3 tools/pii_check.py
```

`wiki/`·`memory/`를 훑어 **걸린 줄의 파일·줄번호만** 알려 주고, **어떤 파일도 고치지 않습니다**(2_서류철은 열지 않습니다). AI에게 **"건강검진"** 이라고 말하면 이것도 함께 돕니다.

## 9. ⛔ 공개 금지 — 이 파일은 나만 봅니다

`dashboard.html`에는 **내 자료의 파일 이름**이 들어갑니다. 파일 이름만으로도 어떤 의뢰인의 어떤 사건인지 짐작될 수 있습니다.

- ❌ 웹에 올리지 마세요 (블로그·홈페이지·공개 저장소)
- ❌ 메일·메신저로 보내지 마세요
- ❌ 백업 저장소(GitHub)에 올리지 마세요

**이건 이미 처리돼 있습니다.** 지식창고를 만들 때 `.gitignore`(백업에서 제외할 파일 목록) 파일이 함께 만들어지고, 그 안에 `2_서류철/`과 `dashboard.html`이 처음부터 들어 있습니다.

```
2_서류철/
dashboard.html
```

확인만 한 번 해 두세요 — AI에게 `.gitignore 내용 보여줘`라고 하면 됩니다. 위 두 줄이 없으면 `.gitignore에 2_서류철/ 과 dashboard.html 을 추가해줘`라고 하세요.
⚠️ `e_확장/GitHub_백업.md`에 적힌 제외 목록에는 `dashboard.html`이 빠져 있습니다. **그 문서를 따라 하시더라도 이 한 줄은 반드시 넣으세요.**

> **명함은 공개, 대시보드는 비공개.**
> 이 패킷에서 바깥에 내보내는 것은 **전자명함 하나뿐**입니다(→ `명함_만들기.md`). 명함은 지식창고 **바깥의 다른 폴더**에서 만들고, 대시보드는 지식창고 안에 둡니다. 폴더를 아예 갈라 두면 "실수로 같이 올리는" 사고가 구조적으로 생기지 않습니다.

## 10. 안 될 때 — 3단계 점검

### 화면이 비어 있고 "아직 숫자를 넣지 않았습니다"라고 나와요

정상 안내입니다. 숫자를 아직 안 채운 것입니다 → 위 **2번**(만드는 법)을 하세요.

### `dashboard.html` 파일 자체가 없어요

AI에게 이렇게 말하세요.

```
f_챗지피티/templates/dashboard.html 을 지식창고의 dashboard.html 과 tools/dashboard_template.html 두 곳으로 복사해줘
```
