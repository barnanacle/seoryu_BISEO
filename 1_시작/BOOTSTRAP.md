# BOOTSTRAP — 지식창고 구축 지침 (AI 실행용)

> **이 문서는 언제 보나**: `0_설치`를 마친 뒤 딱 한 번. 사용자가 AI 앱에 이 파일을 끌어다 놓고 "이대로 만들어줘"라고 말하면, AI가 이 문서를 읽고 지식창고를 만듭니다.

**독자 = AI.** 지금 이 문서를 읽고 있는 AI(Claude 또는 Codex)가 실행 주체다. 아래 0~6단계를 순서대로 수행하라. 사용자에게는 항상 존댓말을 쓰고, 전문용어가 나오면 한 줄로 풀이하라. 한 번에 너무 많은 것을 묻거나 보여주지 마라.

**사용자용 안내 한 줄**: 아래 문장을 복사해서, 이 파일과 함께 AI에게 보내면 됩니다.

```
이 파일(BOOTSTRAP.md) 내용대로 내 지식창고를 만들어줘.
```

---

## 0단계. 안전 규칙 — 시작 전 반드시 지켜라

1. **기존 폴더·파일 덮어쓰기 금지.** 만들려는 위치에 같은 이름의 폴더나 파일이 이미 있으면, 절대 덮어쓰지 말고 멈춰서 보고한 뒤 다른 이름 또는 다른 위치를 제안하라.
2. **생성 전 사용자 확인은 딱 1회.** 2단계에서 전체 계획(위치 + 폴더 구조 + 만들 파일 목록)을 보여주고 승인을 받은 뒤에만 만들기 시작하라. 승인 후에는 단계마다 다시 묻지 마라. 단, 충돌(같은 이름 존재)이나 오류가 나면 즉시 멈추고 물어라.
3. **파일을 읽고 쓸 수 있는지 먼저 확인하라.** 지식창고를 만들 위치(연결된 빈 JARVIS 폴더)에 접근할 수 없으면 작업을 멈추고, 사용자에게 이렇게 안내하라: "① Finder(또는 파일 탐색기)에서 홈 폴더에 빈 `JARVIS` 폴더를 만들어 주세요 ② `0_설치` 가이드 끝의 「폴더 연결」대로 그 폴더를 AI 앱에 추가해 주세요 ③ 그런 다음 '이어서 해줘'라고 말씀해 주세요." (연결되지 않은 폴더에는 AI가 파일을 만들 수 없다.)
4. **이 패킷(install_JAARVIS) 안의 파일은 수정하지 마라.** 패킷은 읽기·복사의 원본일 뿐이다. 특히 이 패킷은 git 저장소(개선판이 나오면 GitHub Desktop의 Fetch/Pull 버튼으로 갱신받는 원본)라서, 안의 파일을 고치면 다음 갱신이 꼬일 수 있다. 모든 생성물은 사용자가 정한 지식창고 위치에만 만든다.

## 1단계. 인터뷰 — 사용자를 알아가기

인터뷰 문항의 표준은 같은 폴더의 **`1_시작/설정_인터뷰.md`** 다. 그 파일을 읽고, 12문항을 **3개 파트로 나눠 물어라 (한 번에 4문항 이하).** 각 문항에 딸린 "왜 묻나" 한 줄을 곁들이면 좋다. 사용자가 "모르겠어요" / "알아서 해주세요" / "기본"이라고 하면 설정_인터뷰.md에 굵게 표시된 기본값으로 대신하라.

- **파트 1 「나에 대해」** (1~4번): 성함·직함, 전문분야, 주요 업무 3가지, 자료 종류.
- **파트 2 「비서 성격 만들기」** (5~8번): 비서 이름, 말투, 보고 스타일, 제안 적극성. → 이 답 4개는 3단계에서 헌법 템플릿의 **「비서 페르소나」 섹션** 플레이스홀더를 채우는 데 쓴다.
- **파트 3 「운영 규칙 맞춤」** (9~12번): 지식창고 위치, wiki 카테고리 확인, 의뢰인 자료 취급 원칙 동의, 백업 계획.
  - 10번(카테고리)은 파트 1의 2·3번 답을 바탕으로 **AI가 먼저 카테고리 안을 제안**하고 확인만 받아라. 확정안은 3단계의 wiki/index.md 조정에 쓴다.
  - **11번(의뢰인 자료 취급)은 기본값으로 건너뛸 수 없다.** 반드시 원칙을 고지하고 동의를 확인하라.

9번의 **기본 위치** (홈 폴더 = 내 컴퓨터에서 내 계정의 개인 폴더):

| 컴퓨터 | 기본 위치 |
|---|---|
| Mac | `/Users/<사용자이름>/JARVIS` |
| Windows | `C:\Users\<사용자이름>\JARVIS` |

답을 다 받으면 **한 문단으로 요약해 보여주고** 맞는지 확인하라. 답은 아래 플레이스홀더에 대응시켜 기억해 둔다.

| 플레이스홀더 | 채울 내용 |
|---|---|
| `{{이름}}` | 파트 1 – 1번 답 (성함·직함) |
| `{{직업·전문분야}}` | 파트 1 – 2번 답 |
| `{{주요 업무 3가지}}` | 파트 1 – 3번 답 |
| `{{비서 이름}}` | 파트 2 – 5번 답 (기본: JARVIS) |
| `{{말투}}` | 파트 2 – 6번 답 (기본: 정중한 존댓말) |
| `{{보고 스타일}}` | 파트 2 – 7번 답 (기본: 핵심 요약 먼저) |
| `{{제안 적극성}}` | 파트 2 – 8번 답 (기본: 먼저 제안해줘) |
| `{{지식창고 경로}}` | 파트 3 – 9번 답으로 확정한 실제 전체 경로 |

파트 1 – 4번 답(자료 종류)은 2단계의 DATA 하위 폴더 이름과 3단계의 wiki 카테고리 설계에 쓴다. 파트 3 – 10번 답(확정 카테고리)은 3단계에서 wiki/index.md를 조정할 때 쓴다. 파트 3 – 12번 답(백업)은 5단계 완성 보고 뒤의 안내에 쓴다.

## 2단계. 폴더 구조 생성 (사용자 확인 1회 후)

먼저 아래 계획을 사용자에게 보여주고 **"이대로 만들까요?"** 라고 물어라. 승인받으면 생성한다. 이것이 0단계 2번의 "확인 1회"다.

만들 구조 (표준 — 이 구조에서 벗어나지 마라):

```
JARVIS/                     ← 이름·위치는 인터뷰 파트 3 – 9번 답 (폴더 1)
├── CLAUDE.md               ← 헌법 (운영 규칙 전부)
├── AGENTS.md               ← 헌법 사본 (Codex용 — 내용 동일 유지)
├── 시작프롬프트.md          ← 매 대화 첫머리에 끌어다 놓는 파일
├── DATA/                   ← 자료 상자: 원본을 넣기만 하는 곳 (폴더 2)
│   └── (분야별 하위 폴더 — 인터뷰 파트 1 – 3·4번 답으로 2~4개 명명. 예: 인허가/, 계약서/, 민원/)
├── wiki/                   ← 지식 창고: AI가 정리·관리 (폴더 3)
│   ├── index.md            ← 전체 목차
│   └── log.md              ← 작업 일지
├── memory/                 ← 기억 노트 (폴더 4)
│   └── MEMORY.md           ← 기억 목차 (한 줄씩)
├── 서류함/                  ← 의뢰인 사건 자료 — wiki에 실명 반영 금지 구역 (폴더 5)
├── 문서작업/                ← 내가 만드는 산출물 (의견서·계약서 등) (폴더 6)
└── tools/                  ← 변환 도구 (폴더 7)
```

- DATA 하위 분야 폴더는 인터뷰 답에서 뽑아 2~4개 만든다 (개수는 위 "폴더 7개" 집계에 포함하지 않는다).
- 지정 위치에 같은 이름의 폴더가 이미 있으면: **비어 있으면** 그대로 써도 되는지 물어보고, **내용이 있으면** 덮어쓰지 말고 다른 이름(예: JARVIS2)이나 다른 위치를 제안하라.

## 3단계. 템플릿 복사·치환

`1_시작/templates/`의 파일을 아래 표대로 지식창고 안에 생성하라. 복사가 아니라 "내용을 읽어 새 파일로 쓰기"로 처리해도 된다.

| 원본 (패킷 안) | 생성 위치 (지식창고 안) | 처리 |
|---|---|---|
| `1_시작/templates/CLAUDE.md` | `CLAUDE.md` | `{{이름}}` `{{직업·전문분야}}` `{{주요 업무 3가지}}` `{{지식창고 경로}}` 4종 + 「비서 페르소나」 섹션의 `{{비서 이름}}` `{{말투}}` `{{보고 스타일}}` `{{제안 적극성}}` 4종 — 총 8종을 인터뷰 답으로 치환 |
| (치환 완료된 CLAUDE.md) | `AGENTS.md` | 내용 동일한 사본 생성 (Codex 앱이 자동으로 읽는 파일) |
| `1_시작/templates/wiki_index.md` | `wiki/index.md` | 기본 카테고리를 인터뷰 파트 3 – 10번에서 확정한 카테고리로 조정 (행정사 예시: 인허가 / 계약 / 민원·행정심판 / 실무노하우 / 기타 관심분야) |
| `1_시작/templates/wiki_log.md` | `wiki/log.md` | 그대로 |
| `1_시작/templates/memory_MEMORY.md` | `memory/MEMORY.md` | 그대로 |
| `1_시작/templates/DATA_안내.md` | `DATA/안내.md` | 그대로 |
| `1_시작/templates/서류함_안내.md` | `서류함/안내.md` | 그대로 |
| `1_시작/시작프롬프트.md` | `시작프롬프트.md` | `{{지식창고 경로}}`를 실제 경로로 치환, 나머지 문구는 그대로 |

생성 후 확인 2가지:
1. 생성한 모든 파일에서 `{{` 표기가 **하나도 남아 있지 않아야** 한다. 남았으면 그 파일만 다시 치환하라.
2. `AGENTS.md` 내용이 `CLAUDE.md`와 동일해야 한다. (앞으로도 헌법을 고치면 두 파일을 함께 고친다 — 헌법에도 적혀 있다.)

## 4단계. 변환 도구 연결

패킷 `2_도구/`의 도구를 지식창고 `tools/`로 연결하라.

1. `2_도구/convert2md.py` 와 `2_도구/hwp2md.py` → `tools/` 로 복사.
2. `2_도구/rhwp/` 폴더(HWP 변환 프로그램)가 있으면 → `tools/rhwp/` 로 복사.
3. `2_도구/` 안에 `venv/`(파이썬 가상환경)가 있으면 **복사하지 마라** — 옮기면 깨질 수 있다. 대신 `tools/도구_경로.md` 파일을 만들되 **형식을 지켜라**: 첫 번째 내용 줄에 패킷 `2_도구/`의 **전체 경로만 한 줄로** 적고(예: GitHub Desktop으로 받았다면 `/Users/홍길동/Documents/GitHub/install_JAARVIS/2_도구`), 그 아래에 "변환 도구는 이 위치의 venv·rhwp를 사용한다"는 메모를 적어라. convert2md.py·hwp2md.py가 이 파일의 경로 줄을 읽어 부품을 찾는다.
4. `rhwp/`나 `venv/`가 아직 없으면: 설치 스크립트가 실행되지 않은 상태다. 사용자에게 `0_설치/설치_점검표.md` 확인을 안내하되, **지식창고 구축 자체는 계속 진행**하라 (변환 도구는 나중에 연결해도 된다). 사용법은 `2_도구/도구_사용법.md` 참조.

## 5단계. 검증 — 체크리스트를 돌리고 완성 보고

아래 항목의 존재를 하나씩 확인하고, 결과를 표로 사용자에게 보여줘라.

**폴더 7개**: ① 지식창고 루트 ② `DATA/` ③ `wiki/` ④ `memory/` ⑤ `서류함/` ⑥ `문서작업/` ⑦ `tools/`

**파일 8개**: ① `CLAUDE.md` ② `AGENTS.md` ③ `시작프롬프트.md` ④ `wiki/index.md` ⑤ `wiki/log.md` ⑥ `memory/MEMORY.md` ⑦ `DATA/안내.md` ⑧ `서류함/안내.md`

**내용 확인 1가지**: `CLAUDE.md`와 `AGENTS.md`의 「비서 페르소나」 섹션에 겹중괄호 `{{` 표기가 **0개**여야 한다 (예: `{{비서 이름}}`이 그대로 남아 있으면 실패). 남아 있으면 3단계로 돌아가 그 파일만 다시 치환하라.

전부 통과하면 아래 형식으로 완성을 보고하라:

```
✅ 지식창고가 완성됐습니다. (폴더 7개 · 파일 8개 확인 완료)
위치: <실제 경로>

앞으로 이렇게 쓰시면 됩니다.
1. 새 대화를 시작할 때마다 지식창고 안의 「시작프롬프트.md」를 채팅창에 끌어다 놓으세요.
2. 첫 자료를 DATA 폴더에 넣고 "자료 넣었어"라고 말해보세요. 제가 정리해 드립니다.
3. 가끔 "건강검진"이라고 말하면 지식창고 상태를 점검해 드립니다.
4. 법령 검색이 필요하시면 2_도구/법령검색_MCP_설정.md 를 보고 설정하세요.

더 자세한 사용법: 3_사용법/매일_쓰는_법.md
```

**사용자 확인 문구**: 위 ✅ 보고와 체크 표가 보이면 성공입니다.

인터뷰 파트 3 – 12번에서 백업을 "GitHub Private"로 답한 사용자에게는, 위 보고에 이어 `4_확장/GitHub_백업.md`를 보면 된다고 한 줄만 덧붙여 안내하라.

## 6단계. 실패 시 — 멈춘 곳을 보고하고 이어서 재시도

- 어느 단계 어느 항목까지 완료됐는지 **목록으로** 사용자에게 보고하라. (예: "2단계 폴더 생성 완료, 3단계에서 wiki/index.md 생성 중 중단")
- 이 지침은 이어서 다시 실행해도 안전하다: **이미 있는 폴더·파일은 건너뛰고**(덮어쓰기 금지 원칙 유지) 빠진 것만 채운다.
- 사용자가 "이어서 해줘"라고 하면 5단계 검증표를 먼저 돌려 빠진 항목을 찾고, 그 항목만 생성하라.
- 같은 오류가 반복되면 `3_사용법/FAQ_문제해결.md`를 안내하라.
