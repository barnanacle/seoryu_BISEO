# FAQ · 문제 해결

## 설치

### Q1. Codex가 저장소나 인터넷에 접근하지 못한다고 합니다

Codex가 보여 주는 인터넷 접근 또는 명령 실행 승인 창을 허용한 뒤 **“이어서 진행해.”**라고 말합니다. 설치 안내는 루트 [`설치프롬프트.md`](../설치프롬프트.md) 하나만 사용합니다.

### Q2. 기존 파일이 있어 설치를 멈췄습니다

설치프롬프트는 기존 파일을 덮어쓰지 않도록 되어 있습니다. 처음 설치라면 비어 있는 새 폴더를 Codex 프로젝트로 열고 같은 프롬프트를 붙여넣습니다. 이미 운영 중인 프로젝트라면 Codex가 보고한 충돌 목록을 확인한 뒤 빠진 파일만 보완하도록 지시합니다.

### Q3. 운영 폴더에 a_부터 f_까지의 설명서 폴더가 보입니다

저장소 원본을 프로젝트로 연 상태입니다. 새 빈 폴더를 Codex 프로젝트로 연 뒤 루트 `설치프롬프트.md`의 회색 상자를 붙여넣습니다. 정상 설치에는 `1_수집자료실`, `2_수임업무철`, `3_문서작업실`, `wiki`, `memory`, `tools`와 운영 파일만 보입니다.

### Q4. 설치가 중간에 끝났거나 일부 파일이 없습니다

같은 Codex 프로젝트에 같은 설치프롬프트를 다시 붙여넣습니다. Codex는 기존 파일을 보존하고 누락된 운영 파일을 보완한 뒤 다시 확인합니다.

## Codex 프로젝트

### Q5. Codex가 내 자료를 읽지 못합니다

현재 Codex 프로젝트가 실제 JARVIS 운영 폴더인지 확인합니다. 다른 폴더를 열었다면 프로젝트를 바꾸고 **“이 폴더의 AGENTS.md를 읽고 운영 구조를 확인해.”**라고 말합니다.

### Q6. 새 대화에서 이전 맥락을 모르는 것 같습니다

새 대화에서 **“AGENTS.md와 memory 인덱스를 읽고 이어서 작업해.”**라고 말합니다. 장기 지식은 대화창이 아니라 `wiki/`와 `memory/`에 남깁니다.

## 자료와 wiki

### Q7. 자료를 넣었는데 wiki가 자동으로 바뀌지 않습니다

자동 감시 방식이 아닙니다. 파일이나 폴더를 지정해 다음처럼 지시합니다.

```text
1_수집자료실 폴더에서 아직 반영하지 않은 자료를 식별해 wiki에 반영해.
```

AI는 처리 대장과 대조해 이미 반영한 자료를 제외합니다.

### Q8. 같은 자료가 중복으로 들어갈까 걱정됩니다

**“처리 대장과 기존 wiki를 먼저 대조하고 중복은 제외해.”**라고 덧붙입니다. 파일 이름만이 아니라 내용과 출처도 비교하도록 지시할 수 있습니다.

### Q9. 사건 자료를 wiki에 넣어도 되나요

사건 원본은 `2_수임업무철/`에 둡니다. `wiki/`에는 개인정보와 사건 고유 사실을 제거하고 다른 업무에도 재사용할 수 있는 판단 기준·절차·체크리스트만 정리합니다. `2_수임업무철/`은 사용자가 명시한 범위만 검토합니다.

### Q10. PDF나 HWP 파일을 읽지 못합니다

`tools/convert2md.py` 또는 `tools/hwp2md.py`로 변환하도록 Codex에 요청합니다. 변환본은 원본 옆 또는 지정한 작업 폴더에 만들고 원본은 수정하지 않습니다.

## 백업과 새 PC

### Q11. 새 PC에서 이어서 쓰려면 어떻게 하나요

기존 JARVIS 운영 폴더를 새 PC로 복원한 뒤 그 폴더를 Codex 프로젝트로 엽니다. 운영 도구가 빠졌다면 루트 `설치프롬프트.md`를 같은 프로젝트에 한 번 붙여넣어 누락된 파일만 보완합니다. 기존 자료는 덮어쓰지 않습니다.

### Q12. 운영 폴더를 백업하려면 어떻게 하나요

`e_확장/GitHub_백업.md`를 참고해 **내 JARVIS 운영 폴더만** 비공개 저장소로 백업할 수 있습니다. 이 절차는 설치가 아니라 개인 자료의 백업입니다.

## 그래도 해결되지 않을 때

Codex에 다음 정보를 함께 줍니다.

- 현재 프로젝트 폴더의 전체 경로
- 보이는 폴더와 파일 목록
- 실행한 요청 문장
- 오류 메시지 전문
- 기대한 결과와 실제 결과

비밀번호·API 키·주민등록번호·연락처 등 민감정보는 가린 뒤 공유합니다.
